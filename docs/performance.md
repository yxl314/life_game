# 性能测量：数据结构、并发与视图刷新

本文记录从旧实现（`LifeBoard`：`std::vector` + 同步串行）到新实现
（`domain::Grid`：连续存储 + `model::SimulationEngine` / QtConcurrent）的实测提升。

> **关于当前代码**：2026 年的分层重构只改变职责与所有权，没有改变
> `src/domain/grid.cpp` / `src/model/simulation_engine.cpp` 中的演化算法。
> 下列数值来自重构前同一算法的测量，路径与类名已按新架构更新；未重新跑基准，
> 但趋势与量级仍具参考价值。设备为变频 CPU，绝对值会有波动。

## 测试环境

| 项目 | 配置 |
|---|---|
| 设备 | aarch64，8 vCPU |
| 内存 | 15 GiB |
| 编译器 | g++ 13.3.0 |
| Qt | Qt 5.15.13 |
| 编译选项 | `-O2 -DNDEBUG` |
| 规则 | 康威 `B3/S23` |
| 边界 | 死亡边界 |
| 初始密度 | 30% |
| 取数 | 预热后 5 次运行的中位数 |

对比基线为重构前的 `LifeBoard` / `std::vector` / 同步实现（已移除），
优化版本为当前 `domain::Grid` / 连续存储 / `SimulationEngine`。

## 1. Domain 串行演化

同一初始局面，比较旧 `LifeBoard::advance()` 与新 `Grid::computeNext()`。
新实现复用两块 `Grid`，避免每代分配。

| 棋盘 | 旧实现 | 新 Grid 串行 | 提升 |
|---|---:|---:|---:|
| 100 × 70（7,000 格） | 0.341 ms/代 | 0.0434 ms/代 | **7.85×** |
| 200 × 150（30,000 格） | 1.267 ms/代 | 0.177 ms/代 | **7.16×** |
| 400 × 400（160,000 格） | 6.743 ms/代 | 0.987 ms/代 | **6.83×** |

主要来源：

- 每格从 `int`（4 字节）降为 `std::uint8_t`（1 字节），提高缓存密度；
- 一维连续存储，活动区域一次性分配并复用，避免每代重新分配；
- 内部区域直接按偏移读取 8 个邻居，跳过边界判断；
- 输出缓冲区复用；同尺寸 `resize()` 不再清零，避免每代构造/清空新网格。

## 2. 并行计算（纯计算部分）

在 8 个 Qt 线程池工作线程下，将行区间切分后并行计算：

| 棋盘 | 新 Grid 串行 | 并行 | 并行加速 |
|---|---:|---:|---:|
| 100 × 70 | 0.0434 ms | 0.209 ms | 0.21×（不值得） |
| 200 × 150 | 0.177 ms | 0.173 ms | 1.02×（持平） |
| 400 × 400 | 0.987 ms | 0.390 ms | **2.53×** |

结论：生命游戏是内存带宽与邻居访问密集型计算，小棋盘上 QtConcurrent 的
任务派发成本大于收益；只有 16 万格以上规模才有明显并行收益。新增的 1500×1000（150 万格）属于高收益区间。
因此 `SimulationEngine` 设置了 20,000 格阈值，小棋盘只提交一个异步任务，
不做多分块。

## 3. 端到端 Model 吞吐

测量包含：快照拷贝、后台缓冲区准备、`QtConcurrent::mapped()` 派发、
`QFutureWatcher` 完成事件、UI 线程双缓冲交换。每次上一代完成立即请求
下一代，没有 QTimer 间隔，因此是管线吞吐上限。

| 棋盘 | 旧同步 | 新异步管线 | 吞吐提升 | 新管线吞吐 |
|---|---:|---:|---:|---:|
| 100 × 70 | 0.300 ms/代 | 0.225 ms/代 | **1.33×** | 4,438 代/秒 |
| 200 × 150 | 1.265 ms/代 | 0.259 ms/代 | **4.89×** | 3,865 代/秒 |
| 400 × 400 | 6.633 ms/代 | 0.337 ms/代 | **19.70×** | 2,970 代/秒 |

100 × 70 时新管线只快 1.33 倍，因为单代计算已降到 0.04 ms，QtConcurrent
的事件与派发开销占了主导；界面现在最高开放 120 代/秒；大棋盘按屏幕刷新率自适应：屏幕刷新率 ≥ 当前代速时逐代刷新，不足时才合并。

## 4. UI 事件循环响应

场景：400 × 400 棋盘，60 Hz 模拟，持续 2 秒；另设 5 ms 心跳定时器，
记录事件循环最大间隔与模拟槽函数在 UI 线程的阻塞时间。

| 场景 | 心跳最大间隔 | UI 线程平均阻塞 | 说明 |
|---|---:|---:|---|
| 空闲 | 6.16 ms | 0 ms | 基线抖动 |
| 旧同步演化 | 20.32 ms | **11.49 ms/代** | 每代直接阻塞 UI |
| 新异步演化 | 6.08 ms | **0.172 ms/代** | 仅快照与任务派发 |

- UI 线程阻塞从 **11.49 ms** 降到 **0.172 ms**，约 **67×**；
- 事件循环最大间隔从 **20.3 ms** 回到空闲基线 **6.1 ms**；
- 计算本身在 Qt 线程池中完成，UI 线程只负责交换缓冲区和广播信号。

## 5. 界面刷新：高代速下的绘制

大棋盘运行时，`BoardPresenter` 读取 `QScreen::refreshRate()`；屏幕刷新率 ≥ 当前代速时
逐代立即刷新，只有屏幕刷新率不足时才按刷新率合并。模拟仍按 0–120 代/秒推进。
小棋盘保持逐代立即刷新。

`BoardView` 原先逐格 `drawRoundedRect` / `drawRect`。250 × 200（25% 存活）
单帧约 5.2 ms，200 代/秒所需的 5 ms 定时器会被重绘挤占，因此界面限制为 120 代/秒；
大棋盘仅在屏幕刷新率不足时合并。

现在演化中把每格压成一个像素后整块缩放贴图；大棋盘按屏幕刷新率自适应更新
（屏幕足够快时逐代，统计与棋盘同一节奏）：

| 场景 | 单帧绘制 | 实际演化速度 |
|---|---:|---:|
| 250 × 200（默认棋盘） | 0.8 ms | 120 代/秒 |
| 400 × 400 | 0.9 ms | 120 代/秒 |
| 1500 × 1000 | 未做正式单代基准 | UI 冒烟测试在 10 代/秒设置下稳定；更高速度需按机器实测 |
| 100 × 70（格子被放大到 8.5 px） | 1.2 ms | 199 代/秒 |

暂停后恢复逐格矢量绘制，圆角与格缝与之前一致。网格线另有一份位图缓存，
只在棋盘矩形、格子尺寸或缩放比变化时重建。

重构后 View 不再接收整块棋盘副本：Controller 把 `const domain::Grid*` 交给 `BoardView`，
因此每帧少一次 160 KB 的 `QVector` 拷贝。

## 6. 代数跳转：快照与重放

回退不保存每一代，而是按间隔存快照（默认每 100 代，可在设置中调整）。
活棋盘仍使用只覆盖活动区域的 `std::vector<Cell>`（250×200 约 50 KB，
1500×1000 约 1.5 MB），保证模拟和渲染的字节访问；快照使用 1 bit/cell 的
`PackedGrid`。1500×1000 快照约 187.5 KB，65 张约 12 MB（未压缩时约 96 MB）。
回退时取最近一张不晚于目标的快照并 unpack，最多重放 99 代；
目标更早时从锚点重放，并显示可取消的进度对话框。

| 操作（250 × 200） | 实测 |
|---|---:|
| 快进 5,000 代（串行重算） | 1.24 s（约 0.25 ms/代） |
| 回退 2,500 代（命中快照） | 25 ms |
| 回退到起点（命中锚点） | 一次拷贝 |

跳转在单个后台线程中串行推进：每代派发一次 QtConcurrent 的开销远大于计算本身，
因此这里不复用并行管线。跳转期间 UI 不逐代刷新，只在结束时广播一次棋盘变化。

- 设备为变频 CPU，绝对数值会有波动；趋势与量级稳定。

## C++17 / 移动语义 / constexpr 的实际使用

| 用法 | 位置 | 目的 |
|---|---|---|
| `std::string_view` | `Rle`、`Rule`、`PatternLibrary` | 解析/查找不复制字符串 |
| `std::optional` | `RleDecodeResult` | 值语义的成功/失败结果 |
| `std::clamp` + `inline constexpr` | `board_limits.h`、`shared/app_settings.h` | 范围单一来源，编译期常量 |
| `constexpr Rule` | `Rule` 构造/`births`/`survives` | 规则位掩码可在编译期求值、易内联 |
| `constexpr Grid::width/height` | `Grid` | 小尺寸查询无函数调用开销 |
| `constexpr shared::normalized` | 设置规范化 | 范围钳制无运行时初始化 |
| `static_assert` | `domain_tests` | 验证 `Rule` 常量表达式与 `Grid`/`Rule` nothrow move |
| move | `Grid`/`SimulationEngine`/`LifeModel` | 1.5 MB 棋盘的 buffer 转移，避免深拷贝 |
| `std::from_chars` | RLE 头部 | 无分配整数解析 |
| `std::to_chars` | RLE 游程编码 | 每个 run 不再 `std::to_string` 分配 |

说明：C++17 的语言特性不会自动让 150 万格的演化变快。真正的性能来源仍是：
连续 `Cell` 存储、按行并行、避免每代分配、`QImage` 批量缩放、粗网格缓存，以及
限制详细绘制的 cell 数。`if constexpr` 在当前代码中没有合适的类型分支，因此没有为了
“用上 C++17”而加入。
